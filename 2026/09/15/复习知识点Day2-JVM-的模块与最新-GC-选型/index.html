一句话记住今天的内容：JVM = 类加载子系统 + 运行时数据区 + 执行引擎（解释器 / JIT / GC）+ 本地接口与服务性接口；垃圾回收从 JDK 9 起默认一直是 G1，追求毫秒级低延迟用 ZGC，追求高吞吐用 Parallel。面试被问”JVM 现在有哪些模块”时，先答”运行时数据区”这张图，再串上类加载与 GC，层次感就有了。

1. JVM 现在有哪些模块

1.1 底层”五件套”（先记这个框架）

  1. 类加载子系统：加载 → 验证 → 准备 → 解析 → 初始化，含双亲委派模型。
  2. 运行时数据区：程序计数器、虚拟机栈、本地方法栈、堆、方法区（JDK 8+ 为 Metaspace）。
  3. 执行引擎：解释器 + JIT 编译器（C1/C2，GraalVM JIT 属于实验）+ 垃圾回收器。
  4. 本地方法接口（JNI）：与 C / C++ 等本地代码互操作。
  5. 服务性接口：JVMTI、JFR、性能监控与诊断（jcmd / jstat / jmap / jstack 都基于它工作）。

口诀：“类、内、执、本、服”五件套。

1.2 “模块”的第二层含义：JDK 的模块化

JDK 9 起”模块”还有另一个意思——JPMS（Java 模块系统）：java.base 是地基，jdk.compiler、jdk.jfr、jdk.management、java.sql 等按需组装，jlink 可以产出精简运行时。面试时如果有歧义，先确认问的是 JVM 运行时结构，还是 JDK 包模块，再展开。

1.3 运行时数据区速查表（必背）

区域 线程 存放内容 常见异常
程序计数器（PC） 私有 当前字节码行号 无
虚拟机栈（栈帧） 私有 局部变量表、操作栈、动态链接、返回地址 StackOverflowError / OOM
本地方法栈 私有 native 方法 StackOverflowError
堆（Heap） 共享 对象、数组、字符串（JDK 7+ 字符串移入堆） OOM: Java heap space
方法区（Metaspace） 共享 类元信息、方法、字段、常量池 OOM: Metaspace

两个高频差异点：

  • JDK 8：PermGen 被 Metaspace 替换，用本地内存（默认无硬上限，靠 -XX:MaxMetaspaceSize 兜底）。
  • JDK 7：字符串池和静态字段已移到堆里，不再属于”方法区”。

2. 版本演进：最新到底有什么不同

JDK 关键点 面试价值
8 PermGen→Metaspace；默认 ParallelGC 老基准，几乎必考”改了什么”
9 G1 成为默认 GC（JEP 248）；JDK 模块化；GC 日志改 -Xlog “默认 GC” 答案从 9 开始变成 G1
11 ZGC 实验版；Epsilon 实验 低延迟方向启动
14 CMS 被移除（JEP 363） 常考”CMS 哪去了”
15 ZGC、Shenandoah 生产可用 低延迟 GC 双雄转正
17（LTS） 密封类等增强；性能与 GC 更稳 很多团队停在这
21（LTS） 虚拟线程（JEP 444）；分代 ZGC 初版 当前新特性重点
23 分代 ZGC 成为默认（JEP 474）；非分代 ZGC 移除 答题更”新”的点
25（LTS，2025-09） 新一代 LTS：对象头等运行时持续优化 企业主要在 17/21，25 了解即可

记结论：JDK 9 ~ 25 默认 GC 全是 G1。

3. 现在垃圾回收用哪个（核心）

3.1 结论先行

  • 默认：G1（JDK 9 起全默认）。
  • 低延迟：ZGC（JDK 15 生产可用；21 起支持分代；23 起默认分代）或 Shenandoah。
  • 高吞吐：ParallelGC（JDK 8 时代默认）。
  • 实验/无回收：Serial、Epsilon。
  • CMS 是历史：JDK 9 弃用、JDK 14 移除。

3.2 选型速查表

场景 选什么 GC 参数 一句话理由
默认/大多数服务 G1（默认） -XX:MaxGCPauseMillis=200 Region 化、暂停目标可调、吞吐均衡
超大堆 + 毫秒级暂停 ZGC -XX:+UseZGC（JDK 21+ 分代） 读屏障+染色指针，暂停与堆大小关系小
吞吐优先（批处理） Parallel -XX:+UseParallelGC 多线程并行回收，暂停可长但吞吐高
其他低延迟选择 Shenandoah -XX:+UseShenandoahGC（JDK 15+） 并发移动对象，语义类似 ZGC
压测 GC 成本 Epsilon 实验开关 只分配不回收

4. 需要注意的点（生产经验）

  1. 别只调堆大小：Xmx 越大，GC 暂停和 Full GC 压力往往越高；先看 GC 日志/指标再调。
  2. 内存分四口：堆、栈、Metaspace、直接内存（Netty/DirectByteBuffer）异常名不同，”OOM”不全是堆。
  3. G1 大对象（Humongous）：超过 Region 一半的对象直接进老年代，频繁大数组会让老年代暴涨、提前 Full GC，考虑池化/分块。
  4. Metaspace 必须兜底：动态代理、CGLIB、热部署会不停生成类，务必 -XX:MaxMetaspaceSize。
  5. GC 日志写法已换：JDK 9+ 用 -Xlog:gc* 代替 -XX:+PrintGCDetails（后者已废弃）。
  6. 排查顺序：jstat -gcutil <pid> 看 GC 频率 → jcmd <pid> GC.heap_info → 必要时 jmap -dump 出堆 → MAT/Arthas 分析。

5. 常见面试题（背这组）

问题 一句话答案
JVM 有哪些运行时区？ 5 个：PC、虚拟机栈、本地方法栈、堆、方法区（Metaspace）
怎么判断对象已死？ 可达性分析（从 GC Roots），不是引用计数
GC Roots 有哪些？ 栈上局部变量、静态字段、JNI 引用、活跃线程等
对象创建路径？ 类加载→内存分配（TLAB 优先）→内存置零→设置对象头→构造函数
为什么 JDK9+ 默认 G1？ Region 化+暂停目标可调，吞吐/延迟折中
CMS 为什么没了？ 碎片多、并发失败回调 Full GC，JDK14 移除
ZGC 为什么停顿低？ 染色指针+读屏障，GC 与业务并发，暂停不随堆增大
三色标记漏标怎么防？ SATB（G1）/ 增量更新（CMS）
Full GC 频繁怎么排？ GC 日志 → jstat → dump → MAT；根因多为大对象/泄漏/元空间
现在默认用哪个 GC？ G1（JDK 9~25），低延迟 ZGC

6. 自测三问

  1. JDK 8 / 17 / 21 各有哪些 GC 相关变化？各说 1-2 个。
  2. 生产出现持续 Full GC，给出完整排查命令顺序。
  3. “默认 GC = G1” 从哪个 JDK 开始成立？
