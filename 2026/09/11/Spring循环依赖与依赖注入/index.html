Spring 循环依赖与依赖注入：从三级缓存到构造器注入

循环依赖是 Spring 面试里的“常青题”，问法通常是：什么是三级缓存？为什么能解决循环依赖？为什么工作中还要抽 Service 或 @Lazy？顺带还会带出注入方式的对比：@Autowired、@Resource、构造器注入、Lombok……这篇文章把这一整套问法串起来，从原理到工程实践一次讲透。

先说结论

Spring 循环依赖这事，要分两个层面看：

  • 技术层面：三级缓存解决“单例 Bean + 字段/Setter 注入”能不能创建的问题，本质是提前暴露半成品引用。
  • 设计层面：循环依赖本身是坏味道，说明职责边界不清；工作中更推荐抽第三个 Service 消除环，实在不行再用 @Lazy 兜底。

一句话：三级缓存是“能不能创建”的答案，抽 Service 是“该不该这样依赖”的答案，@Lazy 是“暂时不想改设计”的答案。

01 什么是三级缓存？它解决什么问题？

三级缓存是 Spring 解决单例 Bean 循环依赖的机制，核心思想是提前暴露半成品引用。

缓存 名称 存储内容
一级缓存 singletonObjects 完全初始化好的成品 Bean
二级缓存 earlySingletonObjects 半成品 Bean（防止重复生成代理）
三级缓存 singletonFactories 工厂，延迟决定要不要生成 AOP 代理

A 和 B 互相依赖时的流程：

简单理解：允许“先给引用，后补完整”，把创建和完成解耦。

02 为什么有了三级缓存，工作中还要抽 Service 或加 @Lazy？

因为三级缓存只解决技术层面能不能创建，不解决设计层面该不该这样依赖。

手段 解决的问题 定位
三级缓存 单例+字段/Setter 注入能否创建 技术兜底
抽第三个 Service 从设计上消除环 推荐
@Lazy 延迟到使用时才解析 不得已的兜底

两个关键结论：

  1. 构造器注入的循环依赖，三级缓存救不了——构造时要新实例，没有“先造空壳”的机会，Spring 启动会直接报错；
  2. 循环依赖本身是设计中的坏味道，说明职责边界没有划清楚。

所以工作中：抽 Service 是消除环，@Lazy 是绕过环。前者治本，后者治标。

03 什么是构造器注入？

依赖通过构造函数参数传入，依赖齐了才能创建对象：

三种注入方式对比：

方式 写法 特点
字段注入 @Autowired private B b; 先 new 空壳再反射塞值
构造器注入 public A(B b) { ... } 依赖齐了才能 new
Setter 注入 @Autowired public void setB(B b) 先 new 再调 setter

04 @Autowired 字段注入 vs private final 构造器注入

维度 @Autowired 字段注入 private final 构造器注入
依赖可为 null 可以 不能（final 必须初始化）
不可变/线程安全 可变 final 不可变
脱离 Spring 单元测试 难 容易，直接 new
循环依赖 三级缓存能救 救不了
依赖显式性 隐藏 一目了然
Spring 官方推荐 不推荐 推荐

字段注入是“先造空壳再偷偷塞值”，构造器注入是“依赖齐了才能造”——后者会把设计问题更早暴露出来。

05 为什么 private final 的 Service 不用写 this.b = b？

因为 Lombok 的 @RequiredArgsConstructor：

Spring 4.3+ 对只有一个构造器的类自动注入，连 @Autowired 都可以不写。本质就是：Lombok 生成构造器 + Spring 自动调用构造器。

06 @Autowired 和 @Resource 有什么区别？

核心差异在出身和查找逻辑：

@Autowired @Resource
来源 Spring 自有 Java 标准（JSR-250）
查找策略 先类型，后名字 先名字，后类型
多候选时 需 @Qualifier 字段名匹配 Bean 名即可
可标注位置 字段/构造器/Setter/参数 只能字段/Setter

07 实际业务里 @Autowired 和 @Resource 有没有本质区别？

单 Bean 场景没区别；同类型多 Bean 时才暴露差异。

唯一值得记住的本质区别：多 Bean 时，@Autowired 按类型会报错，@Resource 按字段名能自动命中。

08 实际工作里到底该用哪种注入方式？

推荐优先级：

  1. private final + 构造器注入（配 Lombok）——最推荐：依赖不可变、易测试、暴露设计问题；
  2. @Resource——习惯字段注入且常遇多 Bean 时更省心；
  3. @Autowired——字段注入里最通用，多 Bean 需配 @Qualifier。

Spring 官方顺序：优先构造器注入，其次 Setter，最后才是字段注入。
