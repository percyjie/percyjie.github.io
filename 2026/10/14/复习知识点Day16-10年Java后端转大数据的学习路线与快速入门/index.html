复习知识点Day16：10年Java后端转大数据的学习路线与快速入门

一句话记住今天：Java 后端转大数据，最难的不是语言，而是「从面向对象思维切到面向数据思维」——把接口/对象换成表/分区/批次，把「一次请求」换成「一批数据」。 所以路线是四段：地基（Linux + SQL + 数据思维）→ 生态（Hadoop/Hive/Kafka/HBase）→ 引擎（Spark 离线 + Flink 实时）→ 工程（数仓建模 + 湖仓 + 调度 + 项目）。10 年后端经验是巨大优势（JVM、并发、分布式、工程能力可直接复用），真正要补的是 SQL 深度、数据建模、计算引擎调优、数据规模下的排障思维。

先说结论

一张图先看全貌，后面按阶段展开：

问题 结论
要学多少东西 组件很多，但核心只有四个：Hive（SQL 数仓）、Spark（批）、Flink（流）、Kafka（数据管道）
最先学什么 SQL + Linux，不是 Scala，也不是 Spark 源码
最难的是什么 不是语法，而是数据建模（数仓分层/维度建模）和数据倾斜这类规模问题
学多久能上手 全职 46 个月；在职每周 1520 小时，约 6~8 个月
10 年经验的价值 JVM、并发、分布式、稳定性治理、工程化——这些在大数据平台里同样稀缺，是降维优势
面试怎么过 离线数仓分层 + 维度建模 + Spark 调优 + Flink 状态与一致性 + Kafka 可靠性，五块打通

一句话概括：大数据不是「更高级的后端」，而是「以数据为中心的批流计算 + 数据治理」。 你要补的是数据视角，不是重学一门编程语言。

01 先认清：10 年 Java 后端的优势与短板

1.1 可直接复用的能力（别浪费）

已有能力 在大数据里对应什么
JVM 调优、GC、内存模型 Spark/Flink Executor 的堆内存、GC、OOM 排查，几乎原样复用
多线程与并发 Spark 的并行度、Flink 的算子并发、线程模型理解
分布式基础（RPC/MQ/Redis/微服务） Kafka、ZooKeeper、YARN、分布式一致性，理解成本极低
工程能力（CI/CD、监控、日志、压测） 数据平台的稳定性治理，很多纯数据背景的人反而弱在这
Spring / Java 生态 Hadoop、Spark、Flink、Kafka 全是 JVM 系，源码都能读

现实一点说：大数据组件几乎都是 Java/Scala 写的，一个懂 JVM 的后端去调 Spark OOM，比一个只会写 SQL 的人快十倍。这是你最大的杠杆。

1.2 必须补的短板

短板 为什么致命 补法
SQL 深度不够 数仓 80% 的活是 SQL，窗口函数、行列转换写不利索直接卡住 每天刷 3~5 道 SQL 题，练到能徒手写连续活跃/同比环比
Linux/Shell 不熟 集群操作、日志排查、脚本调度全在命令行 熟练 grep/awk/sed/find/crontab，能写调度脚本
数据建模思维 只会写 SQL 的是「取数工程师」，会建模的才是数仓工程师 学维度建模、分层理论，动手设计一套主题域
规模思维 单机 100 万行和集群 100 亿行是两种问题 理解数据倾斜、shuffle、小文件、分区裁剪
Scala Spark 生态大量用 Scala，看源码绕不开 学到「能读懂 + 能写 DataFrame/DataStream」即可
实时链路认知 离线是过去时，实时是现在时 Flink 的状态、水位线、精确一次必须搞懂

1.3 心态上要转的三个弯

  1. 从「接口思维」到「表思维」：后端关心一次请求的响应时间；大数据关心一张表的分区、批次、数据量、倾斜。
  2. 从「强一致」到「最终一致」：数仓数据天然是 T+1 或分钟级延迟，追求「可重跑、可对账」而不是「实时强一致」。
  3. 从「调优一个服务」到「调优一个作业」：作业的资源、并行度、数据分布才是瓶颈所在。

02 阶段一：地基期（2~3 周）——SQL、Linux、数据思维

2.1 SQL 是重中之重（占地基期 60% 的时间）

必练清单：多表 JOIN、窗口函数、行列转换、去重取最新、连续区间、同环比、Top N。

例 1：分组取 Top N（ROW_NUMBER）

技巧点：同一天减去递增的行号，连续区间会得到同一个 grp 值，这是「连续 N 天」类题目的通用解法。

例 3：行列转换（explode + collect_list）

2.2 Linux + Shell

  • 文件与文本处理：grep、awk、sed、sort | uniq -c、cut（日志分析天天用）
  • 进程与资源：top、free、df -h、jps、jstack、netstat（后端已有基础）
  • 定时任务：crontab、脚本编排、失败重试与告警
  • 集群相关：SSH 免密、scp、rsync、YARN 命令（yarn application -list）

2.3 数据思维：建立「分层」的直觉

后端写代码会分层（Controller/Service/DAO），数仓同样分层（ODS/DWD/DWS/ADS）。先接受「数据是分层的、可重跑的、按分区组织的」这个观念，后面所有组件都会变得顺理成章。

03 阶段二：生态期（3~4 周）——Hadoop / Hive / Kafka / HBase

原则：理解原理 + 会写 SQL + 会排查，不要一上来啃源码。

组件 作用 掌握到什么程度 面试常问
HDFS 分布式文件系统，所有组件的存储底座 架构（NameNode/DataNode）、块与副本、读写流程、小文件问题 为什么不适合存小文件？读写流程？副本机制？
MapReduce 第一代批计算模型 理解执行流程与 shuffle 即可，基本不用写 shuffle 过程、为什么慢
YARN 集群资源调度 资源队列、Container、提交作业、查看日志 提交作业到执行的流程
Hive SQL on Hadoop，数仓主力 内外部表、分区/分桶、存储格式、执行引擎、数据倾斜 内部表 vs 外部表？分区分桶区别？倾斜怎么处理？
Kafka 数据管道与实时数据源，重点 分区/副本/ISR、offset、消费组、顺序性、幂等与精确一次 如何保证不丢不重？rebalance？顺序消息？
HBase 海量 KV 存储 rowkey 设计、热点问题、适用场景 rowkey 怎么设计？与 MySQL 的区别？
ZooKeeper 元数据与协调 只做了解，知道它管什么 ——

3.1 Hive 建表：分区 + 分桶 + 列式存储

记住三条：分区是为了裁剪，分桶是为了 JOIN 和抽样，列存是为了少读数据。

3.2 Kafka 必须搞懂的三个问题

  1. 不丢：生产者 acks=all + 重试；服务端副本数 ≥ 3、min.insync.replicas=2；消费者手动提交 offset。
  2. 不重：开启幂等生产者（enable.idempotence=true）+ 事务，实现端到端精确一次；业务侧仍要幂等兜底。
  3. 有序：顺序只保证在单个分区内，需要全局有序就用同一个 key 路由到同一分区，或者干脆只用一个分区（牺牲吞吐）。

04 阶段三：计算期（4~6 周）——Spark 与 Flink 是核心战场

4.1 Spark：离线批处理主力

必须掌握的四层：

层次 内容
核心抽象 RDD / DataFrame / DataSet 的区别，惰性求值与 DAG
执行模型 Job → Stage → Task，宽依赖/窄依赖，shuffle 的代价
运行架构 Driver / Executor / 资源模式（YARN、K8s）、提交参数（executor 数、核数、内存）
调优 数据倾斜、shuffle 分区数、小文件合并、广播变量、缓存、内存与 GC

代码示例：用 DataFrame API 做一次离线聚合

数据倾斜的两阶段聚合（面试必考）

4.2 Flink：实时流处理主力

必须掌握的五块：

知识点 关键问题
时间语义 Event Time / Processing Time / Ingestion Time 的区别
水位线 Watermark 解决乱序，forBoundedOutOfOrderness 的含义
窗口 Window 滚动/滑动/会话窗口，增量聚合 vs 全量聚合
状态 State KeyedState、状态后端、状态大小与 TTL
一致性 Checkpoint / Savepoint、精确一次、端到端两阶段提交

代码示例：Kafka → Flink → 结果库的最小实时链路

Spark Streaming vs Flink 怎么选

维度 Spark Streaming Flink
计算模型 微批（micro-batch） 原生流（一条一条处理）
延迟 秒级 毫秒~秒级
时间语义 弱（以处理时间为主） 强（Event Time + Watermark）
状态管理 较弱 强（状态后端、TTL、大状态）
一致性 精确一次（需配置） 精确一次（两阶段提交，成熟）
现状 离线生态无可替代，实时已被 Flink 超越 实时首选

结论：离线用 Spark，实时用 Flink，两个都要会，别只学一个。

4.3 Scala 学到什么程度够用

优先学（够用） 暂时别碰（性价比低）
case class、模式匹配、Option 类型系统、型变、隐式转换的高级用法
高阶函数：map/filter/flatMap/reduce 宏（macro）、Shapeless
implicit 的常见用法（如隐式参数） Cats / ZIO 等函数式框架
能读懂 Spark/Flink 的 Scala 示例 用 Scala 写复杂业务框架

一句话：Scala 是「读源码和抄示例」的工具，不是你的主语言。 Java API 一样能写完 Spark 和 Flink 任务。

05 阶段四：工程期（4~6 周）——数仓建模 + 湖仓 + 调度

这一阶段决定你是「会用组件的人」还是「能做项目的人」。

5.1 数仓分层（背下来）

分层 全称 职责 例子
ODS Operational Data Store 贴源层，原样落地，不做加工 从业务库/MQ 同步的原始表
DWD Data Warehouse Detail 明细层，清洗、去重、标准化、拉宽 订单明细、支付明细
DWS Data Warehouse Summary 汇总层，按主题做轻度聚合 用户日粒度行为汇总
DWT Data Warehouse Topic 主题层，跨域整合宽表 用户全生命周期宽表
ADS Application Data Store 应用层，直接对接报表与接口 各业务指标结果表

口诀：ODS 保真、DWD 清洗、DWS 汇总、ADS 出结果。分层的价值是「复用」——同一份明细可以支撑无数指标。

5.2 维度建模三件套

概念 说明 例子
事实表 记录业务过程，通常是可累加的数字 订单事实、支付事实
维度表 描述事实的上下文，宽而冗余 商品维度、用户维度、日期维度
星型 / 雪花模型 维度是否进一步规范化；数仓一般用星型，因为查询快、易理解 ——

事实表三种类型：事务事实表（一笔一笔）、周期快照表（每天一张库存快照）、累积快照表（订单从下单到完成的各阶段时间）。

维度变化要用 SCD（缓慢变化维）：Type 1 直接覆盖、Type 2 加版本行保留历史、Type 3 加一列存前值。数仓最常用 Type 2。

5.3 湖仓一体（现在的加分项）

形态 特点 代表
传统数仓 Hive + 分层建模，T+1 为主 Hive / Spark
数据湖 存原始数据，schema on read，容易变「数据沼泽」 HDFS + Parquet
湖仓一体 在数据湖上提供事务、schema 演进、时间旅行 Iceberg / Hudi / Delta Lake
实时数仓 流式链路，分钟级时效 Flink + Doris / ClickHouse / StarRocks

5.4 调度与治理

  • 调度：DolphinScheduler / Airflow / Azkaban，重点掌握依赖编排、补数、SLA 告警、失败重试。
  • 治理：元数据管理、数据血缘、数据质量校验（空值率/唯一性/波动）、指标口径统一。
  • 排查：作业慢 → 看数据量、倾斜、shuffle、资源；结果错 → 看口径、上下游依赖、补数影响。

06 快速入门：6 个月学习计划表

周次 主题 实操任务 验收标准
第 1~3 周 Linux + SQL 刷 50 道 SQL 题；写脚本分析 Nginx 日志 能徒手写连续活跃、Top N、同环比
第 4~6 周 Hadoop + Hive Docker 搭单机集群；建 ODS/DWD 表并跑通 ETL 能讲清 HDFS 读写、Hive 分区分桶
第 7~8 周 Kafka + HBase 用 Kafka 造数据、写消费者；HBase rowkey 设计练习 能答不丢不重不乱的方案
第 9~12 周 Spark 写 5 个离线作业；故意制造数据倾斜再优化 能定位并解决倾斜、小文件问题
第 13~16 周 Flink Kafka → Flink → 结果库实时链路；开 Checkpoint 能讲清水位线、状态、精确一次
第 17~20 周 数仓 + 湖仓 设计一套电商数仓分层模型；用 Iceberg 做时间旅行 能画出分层架构图并解释每层职责
第 21~24 周 项目整合 完整跑通离线 + 实时两个项目，写成文档 简历上能写出 3 个技术亮点

在职学习建议：每周 15~20 小时（工作日晚上 12 小时 + 周末 8 小时），坚持 68 个月即可达到可面试水平。

07 项目实战：简历上必须有两个项目

项目 技术栈 亮点怎么写 面试考点
离线数仓（电商） Hive + Spark + DolphinScheduler 分层建模、维度建模、SCD2 拉链、倾斜优化、T+1 SLA 分层理由、拉链表实现、倾斜处理
实时数仓（埋点/订单） Kafka + Flink + ClickHouse/Doris 端到端精确一次、大状态管理、反压排查、分钟级时效 水位线、Checkpoint、精确一次、反压

项目要有「数字」和「取舍」：

  • 数据规模：日增多少条、总数据量多少 TB、作业跑了多少节点；
  • 优化效果：倾斜优化后作业从 3 小时降到 40 分钟；
  • 方案取舍：为什么用 Flink 不用 Spark Streaming，为什么选 ClickHouse 不选 ES。

08 面试高频考点速查

方向 高频问题
Hive / 数仓 内外部表区别、分区分桶、数仓分层、拉链表、指标口径
Spark 宽窄依赖、shuffle、数据倾斜、小文件、内存模型、提交参数
Flink 时间语义、水位线、窗口、状态后端、Checkpoint、精确一次、反压
Kafka 不丢不重、ISR、rebalance、顺序消息、堆积处理
HBase rowkey 设计、热点、与 MySQL/Redis 的取舍
综合 一条数据从产生到报表的完整链路、慢作业怎么排查

09 避坑清单

  1. 别一上来啃 Spark/Flink 源码——先会用、会调优，源码留到有实战问题后再读。
  2. 别先学 Scala 语法细节——够用即可，Java API 一样能干活。
  3. 别只看视频不动手——大数据是「跑出来的」，本地用 Docker 也要搭起来。
  4. 别只学组件不学数仓——不会建模，永远是取数工程师，不是数据工程师。
  5. 别忽视 SQL——它是这个行业的第一语言，比任何编程语言都重要。
  6. 别跳过 Linux——集群里没有 IDE，只有命令行。
  7. 别把大数据当「更高级的后端」——思维要从请求切到数据，从强一致切到最终一致。
  8. 别做教程级项目——把教程项目加上自己的规模、调优、取舍，才是你的项目。

10 一页速查

最后一句：10 年后端转大数据，不是从零开始，而是把「服务端的功底」搬到「数据的战场」上。 把 SQL 和数仓补起来，把 Spark/Flink 练熟，你的工程能力就是别人追不上的护城河。
