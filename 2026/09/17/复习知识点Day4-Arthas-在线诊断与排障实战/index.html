一句话记住今天的内容：Arthas = 免重启的 Java 在线诊断神器。它的核心价值是”不改代码、不重启、直接进生产 JVM 里看线程、看方法耗时、看对象、改日志级别”。面试答 Arthas 就抓三件事：是什么（attach+字节码增强）→ 常用命令（dashboard/thread/watch/trace）→ 用在哪类问题（CPU 高、接口慢、日志排障）。

1. Arthas 是什么

阿里巴巴开源的 Java 在线诊断工具：把一段 agent 通过 Attach API 挂进目标 JVM，用字节码增强（Instrumentation + ASM）注入监控逻辑，从而做到：

  • 不改代码、不重启就能看运行中的类和方法。
  • 支持 watch（参数/返回值/异常）、trace（调用耗时）、stack（调用栈）、tt（调用回放） 等强大能力。
  • 命令行交互（Telnet/WebSocket），轻量、可灰度使用。

对比：jstack 只能拍线程快照；Arthas 是”活的显微镜”——可以盯着某个方法每次调用往里看。

2. 安装与启动（30 秒上手）

进入后先输入 help 看全部命令，输入 dashboard 看全局面板。退出用 exit（不会杀业务进程）；Arthas 服务本身可以 stop 关闭。

安全提醒：Arthas 拥有 attach JVM 的超级权限（能改类、执行表达式）。生产环境别随便暴露，正式环境建议走权限控制/白名单，用完及时退出并按需 stop。

3. 核心命令速查（背熟这 10 个）

命令 作用 一句话示例
dashboard 线程/内存/GC 总览 dashboard
thread -n 3 打印 CPU 最高的 3 个线程 thread -n 3
thread -b 找阻塞中的线程（死锁/锁等待） thread -b
jvm JVM 运行时信息 jvm
sysprop / sysenv 系统属性/环境变量 sysprop java.version
sc / sm 类/方法定位（可带 -d 看详情） sc -d com.example.service.UserService
jad 反编译线上类 jad com.example.controller.OrderController
watch 观察方法参数/返回值/异常 watch com.example.OrderService getStatus '{params, returnObj, throwExp}' -x 3 -n 5
trace 方法调用链路耗时（定位慢点） trace com.example.OrderService createOrder '#cost > 100'
stack 打印调用栈 stack com.example.OrderService createOrder
tt 时空隧道：录调用现场回放 tt -t com.example.OrderService createOrder
monitor -c 5 每 5 秒统计方法调用次数/成功率 monitor -c 5 com.example.OrderService createOrder
logger --name ROOT --level DEBUG 动态改日志级别，不用重启 logger --name ROOT --level DEBUG
ognl 执行表达式（看/改对象值） ognl '@java.lang.System@getProperty("user.dir")'
heapdump 导出堆文件 heapdump --path /tmp/app.hprof
profiler start / stop CPU/内存火焰图（集成 async-profiler） profiler start && sleep 60 && profiler stop

4. 使用技巧（实战精华）

4.1 先”读”后”写”，安全排障

  • 只读命令优先：dashboard、thread、jvm、sysprop、heapdump 不会改 JVM 行为，先摸清全局。
  • 增强命令慎用：watch/trace/tt 会做字节码增强，对高频方法有额外开销。生产紧急排查可以短暂使用，用完执行 reset 还原。
  • 动态改东西先确认后果：logger --level DEBUG、ognl 改值、redefine 热更新，必须先评估影响面，改完持续观察。

4.2 watch 的威力（最常用）

  • -x 控制对象展开深度，避免打出超大对象。
  • -n 控制打印次数，防止刷屏。

4.3 trace 定位”慢在哪”

trace 会展示方法内部子调用耗时，特别适合”接口慢但不知道是 DB、RPC 还是 GC”的场景。

4.4 动态排障三板斧

  1. 日志级别：线上 logger --name com.example.order --level DEBUG，配合热刷新不了日志配置时就不用重启。
  2. 看参数/返回值：watch 一两行命令，不改代码、不重启就能直接看结果。
  3. 看调用栈：stack + thread 组合判断并发路径。

  • 若栈上是业务线程（死循环 / System.out.println 刷屏 / JSON 序列化）：定位到代码行。

5.5 调日志不重启

6. 常见面试题（背这组）

问题 一句话要点
Arthas 原理？ 基于 JVM Attach 注入 agent，字节码增强实现 watchdog/trace，无需重启
和 jstack/jmap 区别？ 它们是快照，Arthas 是”在线显微镜”，可观察方法级行为
watch 和 trace 区别？ watch 抓方法输入输出/异常，trace 看调用链里每一段耗时
生产用 Arthas 注意什么？ 权限管控、只读优先、高频方法慎增强、用完 reset
查接口慢最常用哪个？ trace（含耗时）或 watch + cost
查 CPU 高最常用哪条？ thread -n 3 找最忙线程
改日志级别？ logger --level DEBUG（运行时）
堆导出？ heapdump --path ...，配合 MAT 分析
谁开源的？ 阿里开源；命令可用 help / help <cmd> 随时看

7. 自测三问

  1. 生产接口偶发慢，你会用哪两条命令定位到 RPC/DB/内部逻辑？
  2. thread -n 3、thread -b 各自解决什么问题？
  3. 为什么”用完 reset 还原增强”是生产规范？
